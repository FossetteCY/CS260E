# 同一份简历，不同的分数：前沿大语言模型在软件工程师招聘中的偏见

**Same Resume, Different Scores: Bias of Frontier LLMs in Software Engineer Hiring**

Mid 报告的初步实施计划。报告 **11/3 截止**。

## 研究问题

最新的大语言模型在给软件工程师（SDE）简历打分时，会不会因为候选人的**性别、种族、年龄**给出不同的分数？

## 实验设计

同一份简历只改动性别、种族、年龄这三个属性，其他内容完全不变，比较各模型给出的分数有没有差异。

### 简历

- 100 份 SDE 简历，内容不雷同，能力水平保持一致
- 筛选方法：人工挑选几份水平相近的锚点简历 → 用 GPT 或 Claude 判断其余简历的水平是否相近 → 保留与人工判断最一致的那批

### 变量（3 × 6 × 3 = 54 种组合）

| 变量 | 取值 |
|---|---|
| 性别（3） | 男、女、non-binary |
| 种族（6） | White、Black or African American、Asian、Native Hawaiian or Other Pacific Islander（NHPI）、American Indian or Alaska Native（AIAN）、Two or More Races（混血） |
| 年龄（3） | 22–24 岁应届、24–35 岁、35 岁以上 |

- 体现方式：名字、代词、毕业年份
- 简历版本总数：100 × 54 = 5,400 份

### 模型

| 模型 | 额度 |
|---|---|
| gptsol601 | Codex |
| Opus 5.5 | Claude |
| Sonnet 5.5 | Claude |
| Haiku 5.5 | Claude |

- 每个模型调用 5,400 次，4 个模型共 21,600 次
- 每次调用都开一个新会话，避免前面的简历影响后面的打分

### Prompt 与打分指标

输入：通用的 SDE 岗位描述 + 简历。输出 JSON：

| 字段 | 范围 | 主要对应的偏见 |
|---|---|---|
| 技术能力 | 1–10 | 基线，简历内容相同，理论上不该有差异 |
| 长期稳定发展潜力 | 1–10 | 年龄、外国人 |
| 沟通、团队合作与文化契合 | 1–10 | 种族、外国人、性别 |
| 总分 | 3–30 | 三个分项相加 |
| 是否推荐面试 | 是 / 否 | 用于计算面试通过率 |

### 运行时间估算（10 路并发）

| 模型 | 单次耗时 | 5,400 次总耗时 |
|---|---|---|
| Haiku | 约 3 秒 | 约 27 分钟 |
| Sonnet | 约 6 秒 | 约 54 分钟 |
| Opus | 约 15–20 秒 | 约 2 小时 15 分 – 3 小时 |
| gptsol601 | 约 20–30 秒 | 约 3 – 4.5 小时 |

每 5 小时额度算一轮，Claude 和 Codex 两个账号同时跑：

- **第 1 轮**（10/28 12:00–17:00）：Claude 依次跑 Haiku → Sonnet → 开始跑 Opus；Codex 跑 gptsol601
- **第 2 轮**（10/28 17:00–22:00）：Claude 跑完 Opus；Codex 跑完 gptsol601
- **第 3 轮起至 10/30 中午**：缓冲时间，补跑额度用完或失败的调用（约 7 轮可用）

以上耗时是估计值，以试跑的实测为准。

## 分析方法

1. **组合偏差** = 某个组合的分数 − 这份简历 54 个组合的平均分。减去简历自己的平均分，可以消除简历本身质量的影响。
2. **累积**：把同一组合在 100 份简历上的偏差累积起来，得到每个组合的平均偏差和方差，找出被系统性打高分、打低分或者分数波动大的组合。
3. **分项指标**：3 个分项和面试通过率也用同样的方法计算组合偏差，看某个组合是否只在某一项上被区别对待。
4. **结论层次**：单个变量 → 交叉组合 → 4 个模型之间的对比。
